# Structured task workflow

When the user supplies a problem/brief and desired outputs and says to start, or asks to continue this workflow, read `.agents/skills/task-start/SKILL.md` and follow its routes without requiring individual skill commands or a competition keyword. For example, “문제 파일은 inputs/에 있어. 원하는 결과는 배정표와 조회 화면이야. 시작하자.” is sufficient. Do not impose this workflow on unrelated small edits. This is the task workspace, separate from the public preparation repository.

Read actual task files and preserve their stack and submission rules. Start with rigorous intake, including combined subproblems and their shared constraints. At every phase check for material unknowns; use the manual stakeholder bridge, pause dependent work, and resume only after the copied answer is reconciled. Show phase, current task, blocker, next step and measured time/budget.

Existing task instructions take priority. Ordinary development needs no separate AI-permission declaration; if an assessment applies, follow its actual rules and stop for an active no-AI phase. Never send stakeholder messages or submit an assessment automatically. Do not publish this workspace's task data or work records to the preparation repository.
