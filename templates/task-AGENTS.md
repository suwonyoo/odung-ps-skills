# Structured task workflow

When the user hands over or points to actual task files for implementation in this workflow, or asks to continue it, read `.agents/skills/task-start/SKILL.md`. “문제 자료는 inputs/에 있어” is sufficient; separate desired outputs, a start phrase and configuration values are optional. Read accessible files to determine the goal, deliverables, constraints and time budget; briefly explain the interpretation and proceed. Ask only about consequential information absent or conflicting in the files. Do not trigger on incidental reference attachments, summary-only requests, toolkit maintenance or unrelated small edits. This is the task workspace, separate from the public preparation repository.

Read actual task files and preserve their stack and submission rules. Start with rigorous intake, including combined subproblems and their shared constraints. At every phase check for material unknowns; use stakeholder-bridge and respect the persisted contact mode. If the user has no DM, record none once; use documents, reversible defaults and necessary user decisions without repeating external-contact requests. No DM does not waive hard requirements or resolve pending decisions. Show the Korean phase, task, blocker, next step, measured time/budget and what the user needs to do.

Existing task instructions take priority. Ordinary development needs no separate AI-permission declaration; if an assessment applies, follow its actual rules and stop for an active no-AI phase. Never send stakeholder messages or submit an assessment automatically. Do not publish this workspace's task data or work records to the preparation repository.

Do not wait for a whole phase budget before reporting. Share concrete partial findings, their source, remaining uncertainty, HR changes and next action as they emerge; aim for a short update within about 60 seconds during active work when supported. Distinguish required user action from one optional useful review. Continue independent work without routine acknowledgment. A refreshed clock is not a new analysis result, and a long running tool is not evidence of progress.
