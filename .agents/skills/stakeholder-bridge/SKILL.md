---
name: stakeholder-bridge
description: Handle ambiguous or conflicting business rules discovered at any phase of a timed task through user-operated HR/stakeholder DM. Record questions, pause dependent work, reconcile verbatim copied answers into requirements/models/checks and resume. Use only during preparation or AI-permitted work.
---

The user sends the DM and copies the reply. Never send messages, automate the chat, fabricate a reply or claim independently authenticated HR evidence. Inspect actual task sources, workflow.json questions, intake and model before asking.

1. Classify the unknown: hard-rule meaning, objective order, input/join meaning, delivery/acceptance, or reversible engineering preference. Investigate facts available in local files yourself. Ask HR for business meaning, the user for material tradeoffs; choose routine reversible engineering details yourself and label them AI defaults.
2. Form at most three specific questions with settled prerequisites. Include a concrete conflicting example and explain which result changes. Register each `question ask Q1 --text ... --impact ... --assumption ... --blocks core solver`. Omit blocks to stop all sessions. `--requires Q0` is allowed only after Q0 is resolved. Use `--nonblocking` only for a disclosed reversible assumption that does not silently decide a required hard rule or objective priority.
3. Give ready-to-copy text to the user and pause dependent work. New questions can arise in modeling, build, integration, verification or finish. Existing timed commands for blocked sessions stop and record hr_blocked; unrelated sessions may continue. File ownership and semantic independence still need judgment.
4. Only after the user actually supplies the reply, save it verbatim in a task-local text file and run `question answer Q1 --file inputs/hr/Q1.txt`. The tool records receipt time, hash and user-copied-hr attribution, not the claimed time/identity of an external conversation. An empty reply or silence is not an answer.
5. Compare the reply with the original brief and prior answers. On conflict or insufficient detail use `question conflict Q1 --note ...`, preserve both originals, and ask the smallest follow-up. Never silently assume an informal reply overrides a formal rule. Do not force resolution to meet a deadline.
6. Reconcile answer → requirement IDs → data/model rule or objective → contract/implementation → independent check. Change the real files before `question resolve Q1 --interpretation ... --changed|--unchanged --updates PATH... --checks CHECK_ID...`. The flag is a reasoned classification, not proof that changes were correctly made. For material changes, update intake/task/model/contract and invalidate downstream assumptions; for unchanged meaning, document why existing behavior already meets the answer.
7. Run `resume --note ...` only after all blocking questions are resolved. Unchanged meaning returns to the interrupted phase; material change returns to modeling and requires inputs-reviewed and a fresh contract. Rerun affected checks. A resolved question is not a passing check. Record accepted/modified/rejected AI proposals only when those actions occurred.

questions.md is a generated view of workflow.json. Do not hand-edit it or delete failed/pending records. Keep a nonblocking assumption visible in limits.md and final handoff. If no HR answer arrives, retain the blocker and report the incomplete behavior; continue only independent authorized work.
