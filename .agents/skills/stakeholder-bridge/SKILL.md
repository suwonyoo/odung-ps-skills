---
name: stakeholder-bridge
description: Resolve ambiguous task rules at any phase using supplied documents, user decisions, or user-operated stakeholder DM when available. Remember no-DM mode, pause only dependent work, preserve source attribution and reconcile changes before resuming.
---

Read actual sources, workflow.json, intake and model. Never send messages, invent replies or claim independently authenticated HR evidence. Use `.harness/WORKFLOW_KO.md` for command syntax.

1. Check `workflow.json.contact.mode`. “DM 없음/질문할 담당자 없음” means `contact --mode none --note 'actual user wording'`, retained until the user changes it. It removes the external-DM step; it does not resolve pending questions or erase requirements. Do not ask about DM again at each phase. Missing channel information needs attention only when a material unknown arises.
2. Look up facts in supplied files yourself. Separate hard-rule meaning, objective order, data meaning, acceptance and reversible implementation preferences. When facts are clear, continue without a question. Choose routine reversible defaults, label them as AI assumptions and record their limits.
3. For important unsettled choices, ask at most three ready questions, each with ONE decision, a concrete example, plain meaning, options/cost and recommendation. Do not hide eight questions in three numbered paragraphs. With manual DM, give copyable text for the user; with no DM, ask the user directly only if their decision is necessary. Never imply they know an unavailable external fact.
4. Register material questions with impact, assumption and dependent session IDs. In manual mode, hr-outbox.md accumulates copyable questions from every phase. The user sends them outside the terminal and appends real replies under `## QID` in hr-inbox.md, or pastes them into chat for you to preserve there. Mark `question sent` only after their report; never send a DM. Check the inbox at phase boundaries and checkpoints, and promptly when the user says a reply arrived. Import the explicit source with `question import`; no background watcher or external reception is implied. Continue concrete independent work while waiting instead of ending all work at the first question. A blocking question pauses phase advancement and affected timed runs; independent work may continue. Use nonblocking only for reversible, disclosed assumptions. A prerequisite question must be resolved before asking its dependent question.
5. Record actual evidence verbatim with `question answer --file ... --source SOURCE` or inbox import. Sources: `user-copied-hr` for a real copied external reply; `user-decision` for the user's actual choice/delegation; `provided-document` for an existing supplied document. Never record an AI default as a human reply. Preserve the original separately from your interpretation. Receiving a reply only means answered, not resolved.
6. Assess the latest reply using `question assess`: clear, partial, ambiguous, conflicting or delegated. Preserve what it does settle and what it leaves open. “가능한 한/적절히/상황에 따라” alone does not define a cap, quantifier, objective priority or exception. For partial/ambiguous/conflicting replies record `--remaining` and a concrete `--followup` contrasting two outcomes or a boundary; dependent work remains paused. Save the next real reply in a new file and append it with `question answer` on the same ID, preserving the original; do not overwrite an inbox section or misuse `--requires` for clarification of an unresolved question. Reassess only after new evidence. Clear replies require plain meaning, a concrete example and expected result. The runtime stores your assessment; it does not reliably detect vague language itself.
7. “이번 질문은 넘기고 추천대로 해” may explicitly delegate a reversible implementation choice: use `ask --kind implementation`, preserve the actual instruction and chosen assumption, then assess delegated with a concrete expected result. Delegation cannot settle unknown business facts or waive a documented hard rule. If an essential fact has no defensible interpretation, keep it unresolved and the dependent behavior unverified; continue independent work instead of repeating unavailable DM requests. Reconcile evidence → requirement → model/objective → contract/code → independent check. Update actual files before resolve with changed/unchanged, paths and check IDs. A current clear/delegated assessment is required. Conflicting evidence stays recorded; do not assume an informal reply overrides formal rules.
8. Revise the remaining-work plan when a reply introduces rework or waiting threatens the budget; keep HR wait duration unknown until observed. Do not count parallel waiting twice or pretend an unavailable reply takes zero time. Resume only when blocking questions are resolved. A material change returns to modeling and requires renewed intake/contract and checks; unchanged meaning returns to the interrupted phase. Resolution itself is not verification. Keep nonblocking assumptions in limits.md and final handoff.

questions.md is generated from workflow.json. Do not hand-edit it or delete failed/pending history. Source labels establish provenance, not the truth of an interpretation.
